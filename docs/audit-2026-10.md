# Engineering review — October 2026

This review covers application state, input, display/power boundaries, SD and EPUB
imports, cache/bookmark persistence, AP transport, and the new Markdown/math path.
It is a record of concrete findings and regression evidence, not a claim that all
possible firmware or rendering defects are eliminated.

## Fixed findings

| Finding | Change | Regression evidence |
|---|---|---|
| Closing-punctuation lookahead could repeatedly scan the remaining paragraph | Stop at the bounded hang budget and yield cooperatively | `english_layout` adversarial work bound |
| Resume fields could represent different saves; library indices changed after rescans | One checked versioned resume record, selected by path; legacy fields remain read-only | `resume_state` write/read faults, reorder and truncated records |
| Out-of-range saved offsets could become another reading position | Reject invalid records without overwriting them | `reader_integration`, `cache_adapter` |
| Saving immediately after reflow snapped the original source offset backward to a page start | Retain the exact anchor until a real page turn; restore it on validated cache load | `reader_integration` alternates layouts eight times without extra writes; `cache_adapter` retains an in-page offset |
| Shutdown could stop networking before a failed persistence operation | Stop the radio only after required saves succeed | Lifecycle source review; persistence failure tests |
| Lost AP start/commit responses could create an ambiguous second import | Stable request identity, offset status and four bounded completion receipts | `network_integration`; six tests executing the real browser script |
| STA timeout continued from the original connection attempt after a later disconnect | Reset the grace window on connection loss | `network_integration` |
| Generated list markers were lost at source-offset page boundaries | Map generated markers to non-empty original syntax ranges | `markdown_document`, `markdown_pagination` single-line pages |
| Inline code inherited paragraph hyphenation | Check the run at the actual break before adding a discretionary hyphen | `markdown_pagination` |
| Opposing large formula ascents/descents could exceed a fresh page together | Include combined vertical extents in line fitting | Real nested-matrix regression in `markdown_pagination` |
| Later formula allocation failure could erase an already accepted formula | Preallocate workspace and bounded command slots before admission | `markdown_runtime` forbids later allocations and compares repeated page pixels |
| Vendor parser allocation failures exposed unsafe cleanup paths | Three narrow MD4C cleanup fixes with documented upstream provenance | Per-allocation failure injection and moving realloc in `markdown_document` |

See the [bounded research results](research-2026-10.md) for exact-anchor
preservation, battery pixel deduplication, Markdown metric caching and the
remaining SD/EPUB semantic bottlenecks.

## Architecture decisions

- Keep application navigation and the SD catalogue on one owner task. Parallel
  host work does not imply concurrent device-side mutations.
- Share format detection/quotas between SD discovery and HTTP admission through
  `document_format`. Keep the transport and format parsers independently testable.
- Split Markdown into source-preserving parsing, object pagination, mathematical
  layout, native font data and the display adapter. Preserve original byte offsets
  across all these boundaries; generated presentation bytes never become bookmarks.
- Reuse the existing English/CJK line breaker and current EPUB/TXT layout IDs.
  Markdown has a separate cache ID and cannot overwrite a valid cache with a
  temporary whole-source fallback layout.
- Reserve a reusable 128 KiB math workspace plus eight bounded command slots.
  Admission failure remains recoverable with original source text. No formula
  parsing allocation is needed during later indexing or drawing.
- Keep LAN transport as a [design proposal](lan-design.md). Extracting an upload
  store is justified when a second transport is implemented; introducing a generic
  server framework now would add untested lifecycle paths.

## Validation and remaining boundaries

The native suite uses ASan/UBSan, production modules, fault-injecting storage/radio
boundaries, original browser JavaScript, fixed public fonts and synthetic documents.
C++11/no-exceptions and the pinned ESP32 toolchain are checked separately from the
C++17 host suite. Native tests validate logical pixels, not panel ghosting or real
battery current. Hardware records stay outside the public repository.

Mathematics is a bounded TeX subset. Unsupported commands, missing glyphs and
oversized formulas preserve their complete source; tables remain source text.
There is no general font shaping engine, EPUB illustration renderer, USB storage
implementation, folder manager or LAN receiver in this snapshot. Chinese typography
experiments are [opt-in host prototypes](epub-typesetting.md); the device default
is unchanged. See [format limits](markdown.md),
[operation](usage.md) and [power evidence](power.md).
