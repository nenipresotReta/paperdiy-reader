# 打开性能、预处理与多语言排版

[English](performance-research.md)

本文区分已实现行为、工程推论和提案，涵盖打开成本、缓存信任、章节边界恢复、浏览器预处理和有界多语言排版。基准应使用合成或可公开再分发的夹具，不记录个人设备操作和阅读数据。模块索引见[架构与实现](architecture-and-implementation.zh-CN.md)。

## 1. 优化读者实际等待的时间

“打开时间”包含不同工作：

| 场景 | 必要工作 | 应消除的无用工作 |
| --- | --- | --- |
| 新 EPUB 首次打开 | 验证源、解码相关资源、提取、排版、显示一页 | 测量时逐字绘制、反复读取整个归档 |
| 相同排版、书籍未变 | 验证复用身份、读取缓存、恢复锚点、绘制 | ZIP/XML 解析与全书分页 |
| 字体或边距改变 | 复用已验证文本/语义，计算新页几何 | 仅因排版改变就重新导入源 |
| 重启恢复 | 重建源信任，加载内容/排版与精确锚点 | 重写未变状态或重做有效提取 |
| 同会话重开 | 在受控 SD 所有权 epoch 内复用源验证 | 重复哈希同一未变源 |
| 准备中断 | 恢复完整旧代或有效检查点 | 发布半成品或丢失阅读锚点 |

至少记录 `source_verify_ms`、`cache_read_ms`、`extract_ms`、`semantic_ms`、`paginate_ms`、`cache_write_ms`、`first_paint_ms`、总时间、读写字节及缓存结果。只有命中次数、没有字节计数，可能掩盖数 MiB 源重读。主机耗时与电子纸刷新耗时分开测量。

第一阶段在不改变进度语义的前提下减少完整打开工作。渐进分页先显示保存源锚点附近的一页，再计算 EPUB 后续页面。未知页码/总数明确显示 `…`，页脚提示索引/缓存进行中。因此完整索引时间和首个可读页面时间必须分开。

## 2. 成本模型与可达边界

令 `A` 为归档字节、`X` 为访问的解码 XHTML 字节、`T` 为 UTF-8 提取字节、`E` 为 ZIP 条目数、`S` 为 spine 条目数、`M` 为 manifest 条目数、`G` 为字形数、`P` 为页数；`R`/`W` 为实测 SD 顺序吞吐，`F` 为显示刷新时间。

全部工作完成后才显示的严格冷打开成本为：

```text
源验证：    A / R                          若必须哈希全部源字节
导入：      相关 ZIP 读取 + inflate(X) + XML(X)
索引：      至少 Ω(G)                       精确全书页数
缓存发布：  cacheBytes / W + readback / R
首屏：      F
```

渐进 EPUB 将完整索引及已校验缓存发布移到首屏后。关键路径仍包括完整源/内容验证或提取、锚点定位、一个本地页面测量及刷新。`Ω(G)` 工作没有消失，只是以有界前台循环片段继续；感知等待缩短不等于 CPU/SD 总工作减少。

基线 SD SPI 为 4 MHz。即使零开销，最多也只有每秒 500,000 字节，完整读取 64 MiB 归档的下界约 134 秒；20 MHz 的理想下界仍约 27 秒。FAT 查找、SPI 帧、卡延迟及哈希只会增加时间。这是物理吞吐上界推算，**不是实测速率**；软件无法在这两种链路上对如此大文件实现亚秒级严格验证。当前源码依次尝试 20/10/4/1 MHz、400 kHz，挂载时验证根目录，发现读取失败后降低下次挂载上限。高频仍需实卡验证，卡容量不是性能保证。

官方 Arduino [PaperDIY microSD 示例](https://docs.m5stack.com/en/arduino/paperdiy/microsd)继承通用 `SD.begin()` 的 4 MHz 默认值，并非板级速度上限。官方[出厂固件](https://github.com/m5stack/M5PaperDIY-UserDemo/blob/main/main/hal/hal_tf_card.cpp)使用未降频的 `SDSPI_HOST_DEFAULT()`，其 ESP-IDF 5.5.1 [默认值为 20 MHz](https://github.com/espressif/esp-idf/blob/v5.5.1/components/esp_driver_sdspi/include/driver/sdspi_host.h)。这支持在实际卡上受控比较 4/10/20 MHz 读哈希并保留保守回退，但不能证明所有卡或 Arduino 传输均有同样吞吐/可靠性。

正确性也限制缓存捷径。同大小、同 mtime 文件仍可能字节变化；只采样首尾或哈希 ZIP 目录不能证明所有压缩数据未变。CRC 可检测意外损坏，不能使未读取内容可信。可行快路是明确的当前独占存储会话：验证一次，只复用到任何可能改变源的事件发生为止。

仅改变排版应接近 `O(T + P)` 读取/测量/索引，不再解压归档。完整 EPUB 缓存可带认证块清单，保留全局元数据/页偏移，只将当前页和有界上下文块读入原有绝对偏移地址空间。冷打开仍验证完整源并预留 4 MiB 文本；这减少缓存文本 I/O，不是常数时间冷打开或流式 ZIP 提取。

### 约束可能超线性的路径

基线导入器按名称搜索 ZIP、为每个 spine 引用查找 manifest，最坏分别为 `O(S × E)`、`O(S × M)` 字符串比较。排序索引（构建 `O(E log E)`、查找 `O(log E)`）或有界哈希索引可消除重复扫描，特别适合含数千图片/小章节的书，但必须明确索引内存和分配失败上限。

字形循环若反复回扫行首，长行可由线性退化为平方；应携带上下文或每行计算一次。前看必须有固定候选预算，不能递归枚举断行序列。零宽 run、重复标点、不可断标识符和深层标签需要对抗夹具。

让出执行应依据时间/工作预算。每个 ZIP 条目或小块 delay 一个 tick，即使计算很少也可能累积数秒；完全取消让出又会饿死输入、网络或 watchdog。应同时记录最大连续工作和让出次数。

## 3. 缓存分层与完整性约定

不同产物使用独立身份：

```text
源字节 + 提取器版本
    -> 规范文本 + 语义范围
       文本/语义摘要 + 排版/字体/几何身份
           -> 页/行索引
              当前页 + 显示状态
                  -> 像素
```

排版变化只失效排版产物。提取器变化使内容失效；若规范文本改变，还需要进度迁移。字体变化可改变页面度量，但不改源码。临时回退不能覆盖已验证的完整语义。

验证 memo 可局限于一个源验证/存储 epoch，绑定路径、大小、mtime 和完整摘要；重新挂载、换卡、读写错误、源修改及每次 USB 块设备交接均失效。当前休眠门禁也会在停用 SD 边沿 ISR 前撤销证明，因该期间无法排除移除/重插。已加载页保留，但休眠后重开重新验证源。mtime 可快速拒绝候选，不能替代初次摘要；不能把 memo 跨重启持久化为“卡一直独占”。

暴露缓存状态前仍验证大小、校验和、UTF-8/源边界、语义顺序/引用及页偏移。完整临时产物经回读后才发布，进度迁移成功前保留旧代。内容与排版缓存需要独立提交/回退，不能因分页失败破坏恢复书签所需的唯一副本。

局部可见窗口和规范页前缀使用不同向量；只有完整规范索引才能进入完整缓存。独立双槽日志保存有界规范页前缀及下一游标，绑定排版、提取/语义版本、源路径、重新验证的依赖图、完整文本和序列化语义。恢复延续后台工作，但不移动可见页或精确锚点；未完成前缀不提供全书总数。

每槽最多 65,536 个偏移，两槽合计最多 524,624 字节。首存从 32 页开始，后续要求新增至少 128 页且距成功保存五秒。读写/回读每步最多 8 KiB。取消保留有效旧槽和完整缓存。截断、撕裂、错误身份或损坏前缀均拒绝；重新启动必须先验证源。

### 已实现的章节提取恢复

`Importer::begin()` 建立已验证章节计划，`stepChapter()` 导入完整一章，同步 `run()` 使用相同路径。正常 `sd_open::Job` 每次 poll 推进一章或一次日志 I/O。字节块、解析器和树遍历观察回调用于协作调度/锁存取消，不挂起 DOM，也不能抢占阻塞文件系统操作。取消在当前章和必要提交后才成为终态；启动与预处理工具保留同步封装。

`.exttext` 独立保存最多 4 MiB 规范前缀。两个 `.ext0`/`.ext1` `PXE1` 提交各有 192 字节头、最多 1 MiB 元数据，每书合计最多 6 MiB 加 384 字节。提交绑定完整源/依赖证明、带长度边界的章节计划、版本、游标、前缀长度/摘要和显式 `ECS1` Collector 状态。ECS1 头 96 字节、编解码上限 525,536 字节、默认容量最大 398,560 字节；保存记录、资源/路径、语言表、数学/TeX 和状态，单凭展平 PDS 无法重建 Collector 可变尾部。

仅关闭的章节可恢复。追加不能修改已提交文本前缀；最终语义裁剪可更新早期记录，因此每次保存完整 Collector。首个非空前缀可保存，此后需新增至少 256 KiB 或 64 章且经过一秒；取消/完成请求保存。新后缀、元数据及回读每次最多 8 KiB；打开、flush、rename 仍同步。恢复前重新验证源及所有已读目录依赖，大小/mtime 不足为证。无效新槽可回退有效旧槽；两槽都失败则重新建立初始化/标题/Collector 后再追加。

SD 策略允许 Collecting、Complete 和确定性的 Budget/Invalid 回退。分配失败或整次纯文本重试只保留会话内结果，不能替换更完整语义。部分提取不发布普通书籍键、书签或 NVS 进度。完整提取可独立于页索引检查点，在分页中断后复用。每次 poll 和发布均要求同一个非零 storage lease，即使可选日志不可用。当前测试覆盖逐章重启及规范文本/PDS1/PDS2/PDS3 逐字节一致；硬件冷导入/中断耗时需要独立且可复现的基准。

### 已实现的首屏与延迟发布

新导入 EPUB 和重排先测量精确保存偏移周围一页。显示起点可回看 UTF-8/拉丁单词上下文，但原偏移仍是持久化权威。可见窗口最多 32 页；前进只测量下一所需页，深窗口之前回退从前移 4 KiB 的种子开始，应用有界词/UTF-8 调整，最多测量 16 页，不从书首扫描。排版改变时临时页面可略重叠，但不能跳过下一未读字节。

规范索引从字节零开始，每次应用循环最多两页、软预算 12 ms；单页可能超时，原排版协作仍服务 watchdog。只在 Reading/Library 前台操作之间、按键空闲时运行。完成不替换当前页，仅更新页脚精确总数；下次主动导航采用规范边界。文档指针、文本长度、书签键及排版/样式身份防止旧任务修改新书。

进度成功保存后，`DeferredCacheWrite` 快照完整元数据/页表、借用稳定文本，每步最多写 8 KiB；摘要回读和旧主/备份验证也分步。每步检查 storage lease，取消不能清理替换卡。临时文件完整校验后才发布。打开、flush、rename 是不可分文件系统调用，字节限制不保证硬响应时间。

该机制用于 EPUB；兼容完整页缓存走直路，TXT/Markdown 仍同步索引，不流式处理 XHTML，也不绕过冷源全验证。后台任务使 Reading/Library 保持活动，因此首屏更快不等于能耗更低。进入 Settings 暂停；存储所有权撤销会取消 SD 发布，但仍独占 RAM 文档的索引可完成；换书/卡/排版及关机明确取消相应任务。测量边界和合成回归矩阵见[第 9 节](#9-基准与回归计划)。

### 已实现的缓存文本窗口

`DeferredCacheWrite` 发布完整缓存时计算每 8 KiB 文本块 SHA-256，再可选发布已校验 `.chunks`。清单绑定完整缓存摘要、全局元数据/页前缀和各文本块；4 MiB 文档最多 16,504 字节。清单缺失/过期/损坏走独立完整缓存路径，暴露窗口前仍重建源信任。

翻页先固定认证块再移动锚点。每块先在暂存区验证再复制，只暴露完整且已验证 UTF-8。元数据可不触碰未加载文本而解码，再在固定范围内验证依赖文本的边界。水平、竖排、混合模式遵守范围末端。异常语义跨度可回退完整验证加载；失败保持原可读范围和精确位置。lease 丢失允许使用已验证 RAM，不允许新增 SD 读取。

合成主机回归显示约 1 MiB EPUB 缓存在深锚点处以少于 128 KiB 缓存读取、低于 64 KiB 驻留跨度打开，同时仍哈希完整源。实际 reader 测试在 ASan 下毒化全部未固定字节，对照全驻留的纯文本、水平语义、竖排、混合基线比较页末和绘制几何。这是正确性/字节工作结果，不是设备计时。

EPUB 在大小不变的 v3 extension 中明确 `semanticRevision=2`。旧 0/1 仅用于书签迁移，即使 family 相同也不能提供普通页面或重排文本。重新导入在规范字节相同时仍优先保留当前内容键的精确偏移。TXT/Markdown 仍用语义版本 0 和经审计文本 family 复用。最终原生 ruby 几何使用 `0x2026a000`；中间 `0x20268000` 只验证/迁移精确锚点，不提供当前页面或重排文本。语义版本 2、预处理 extractor2 不变。

## 4. 其他阅读引擎的启示

[CrossPoint 缓存格式](https://github.com/crosspoint-reader/crosspoint-reader/blob/develop/docs/file-formats.md)分离书籍元数据与章节/页面产物，其[章节实现](https://github.com/crosspoint-reader/crosspoint-reader/blob/develop/lib/Epub/Epub/Section.cpp)使用版本化 complete/incomplete/partial 状态，并在挂起构建时保存完成页。可借鉴的是章节局部工作及显式发布状态；内存目标、格式、UI 不同，其计时不是 PaperDIY 基准。

[KOReader CREngine 文档实现](https://github.com/koreader/crengine/blob/master/crengine/src/lvtinydom.cpp)区分 DOM、缓存格式、格式化版本并处理 bookmark/XPointer 兼容；[document view](https://github.com/koreader/crengine/blob/master/crengine/src/lvdocview.cpp)也分离渲染失效与文档状态。启示是各层显式兼容身份。整体替换为大引擎属于移植、内存和许可证项目，不是小优化。

这些一手源码用于架构研究。采用代码前须审查许可证；本项目实现自身有界机制。分支链接可变，生产依赖或复制算法需固定版本和来源记录。

## 5. 可选主机/手机预处理

[预处理指南](prepared-content.zh-CN.md)记录原生/浏览器构建和 AP 传输工作流。

### 可移出的工作

昂贵且依赖源的工作是 ZIP 遍历、inflate、XML 验证、归一化和语义提取。桌面助手可在传输时做一次，手机可在浏览器页面打开时执行。只有字体度量、排版版本、几何及语言策略与固件完全一致，才能预计算设备页面。

首个可靠约定是**已验证预处理内容**，不是预渲染截图：

- 原 EPUB 保持权威，且能独立阅读。
- 由设备同一 C++ 导入器生成文本/有界语义。
- 完整源 SHA-256 和 extractor ID 绑定预处理结果。
- 文本与元数据共用 payload 摘要；显式小端字段/字节数。
- 旁车是可丢弃优化；缺失/过期/无效时设备导入。
- 首版不含页偏移；设备字体/设置决定分页。
- 保留源路径/内容书签身份，不能将旁车变成无关第二本书。

包内源哈希不能证明任意发送者提取内容诚实。哈希检测不匹配/损坏并识别预期源；准入依赖用户明确的本地准备/传输信任及有界验证。认证传输授权发送者，不从数学上证明任意文本等价于 EPUB。重新完整导入会抵消卸载收益。

### 预处理封装

`PDT1` 使用 160 字节头，随后是精确文本和元数据，独立于设备页缓存结构：

| 偏移 | 字节 | 字段 |
| --- | --- | --- |
| 0 | 4 | ASCII `PDT1` |
| 4 | 4 | 小端格式版本 |
| 8 | 4 | 头长，必须 160 |
| 12 | 4 | extractor 身份 |
| 16 | 8 | 原 EPUB 字节数 |
| 24 | 4 | 文本字节数 |
| 28 | 4 | 元数据字节数 |
| 32 | 32 | 原始源 SHA-256 |
| 64 | 32 | 文本接元数据的 SHA-256 |
| 96 | 4 | 语言枚举：0 无、1 en-US、2 en-GB |
| 100 | 60 | 保留零字节 |

未知版本/extractor/语言、非零保留位、超限/不一致长度、无效 UTF-8、错误元数据/摘要均拒绝。源最多 64 MiB，文本最多 4 MiB，元数据由共享 `epub_metadata_limits` 限制为 352,808 字节；与设备共用有界编码器/验证器，不使用主机指针布局。零元数据表示明确纯文本回退，不能伪称完整语义。

当前 extractor ID 为 2，旧预处理需重做。`example.epub.pdt` 随原源命名，不列为书籍；封装权威为 `src/prepared_epub.h`，PDS 编解码为 `src/epub_document.h`。元数据保留局部 run 语言、资源顺序、段落 ID 及语义标志；不含 Wi-Fi、进度或本地路径。

### 实现工作流与证据

CLI 使用生产 C++ 导入器，只接受本地源。写入前后重新检查源指纹，在临时文件中准备/验证，再原子发布且不覆盖已有目标；该发布依赖 POSIX 硬链接，不等于 FAT exactly-once。原 EPUB 不重写。

AP WebUI 将选择的 `File` 交给 `prepare_worker.h`，不在 UI 线程读取完整归档。Worker 从认证同源 `/prepare-core.js`、`/prepare-core.wasm` 加载，报告阶段，将文件复制进有界 WASM 堆，将复制的结果 buffer 转移回页面。取消直接 terminate Worker，因为消息不能中断同步 native 调用。页面必须保持打开，不承诺手机常驻/后台服务。准备失败可仅上传原书；源上传成功、旁车失败可按设备实际返回名称仅重试旁车。

生产模块初始堆 16 MiB、最大 128 MiB、栈 256 KiB。文件缓冲、JS/引擎/UI 内存在该上限之外；手机可能更早耗尽内存，因此 64 MiB 是格式上限，不是手机内存保证。导入后、打包结果前释放源存储；不需要 CDN、网络转换、SharedArrayBuffer 或远程 JavaScript。

记录的一次 Emscripten 4.0.18 集成构建产生 JS 13,483 字节、WASM 91,067 字节；确定性 gzip 后为 3,991、42,449 字节，核心共 46,440 字节，未计小 Worker wrapper。固件以每 poll 2 KiB 从 flash 流出，使用认证路由、正确 MIME/gzip 和独立 1 MiB 响应上限，不分配资源大小的 RAM 响应。提交产物是文本 C++ 头，原始构建产物留本地；独立目录 `--check` 曾逐字节再生一致。

实际 WASM 与原生工具比较完整 PDT，108 个成功案例逐字节一致、94 个预期拒绝，包括精确 64 MiB 归档；复用生产 EPUB 语义/纯文本夹具。真实 Worker wrapper 使用真实 WASM 也一致；强制取消、独立 16 MiB 堆的源/文本分配失败和恢复均通过。这是主机执行证据，不证明手机浏览器速度、后台行为或最终设备 AP 传输。较晚真实浏览器 localhost 测试在生产 CSP 下完成源/旁车配对并正确处理服务端改名，见第 9 节；不使用 ESP32 AP，也不改主机网络。

不能以“优化”为由自动删除源归档中的字体、插图、样式或章节。另选转换输出可以有用，但会改变源、身份及支持语义；旁车准备可逆且保持源不变。

## 6. 英文排版：四项有界改进

当前源码实现以下机制，但不宣称完整浏览器/TeX 排版。`line_quality.h` 限制局部测量；生成的 `latin_metrics.cpp` 通过 `latin_metrics.h` 提供唯一原生字体表；`epub_document.h` 保留支持的语义；`text_language.h` 选择 US/GB 规则。实体设备验证独立于这些主机与源码检查。

### 6.1 有界段落前看

贪心只优化当前行。有界两/三行候选搜索可通过移动一个词，避免过松行或多余连字符；以归一化空格伸展、断词、连续断词、过短末行、页边约束评分。固定候选/词/字节预算，用尽后确定性回退。

参考 [Knuth 与 Plass《Breaking paragraphs into lines》](https://doi.org/10.1002/spe.4380111102)的全局段落优化模型，但嵌入式有界前看最优性更弱，不能称完整 TeX 段落组合。应在合成不均匀词长/长段夹具证明改善，并限制完整索引时间退化。

### 6.2 字体 kerning 与精确 advance

kerning 来自所选字体，不能手猜 `AV` 偏移。提取支持拉丁字对的有界调整，用定点保留小数 advance，在累计绘制位置取整；测量/绘制使用同一字对状态。样式、行首、显式空格、源屏障、数学原子处重置。

原生位图仍可使用小数位置累计，不代表缩放或抗锯齿。连字需要独立的源字符簇到字形映射。[HarfBuzz shaping 文档](https://harfbuzz.github.io/shaping-and-shape-plans.html)解释 advance/offset/cluster，可用于未来主机 shaping；固件接入完整 shaper 前需内存/正确性审查。字对 kerning 不是完整 shaping 或 grapheme 支持。

### 6.3 保留书籍结构

使用导入器语义范围保存标题、引用、列表、强调和预格式文本。标题可与后续正文保留，引用可有界缩进，代码保留空格；保留段落身份，不事后从重复换行猜测。只用原生字号时，应选择明确原生强调或克制样式，不缩放模拟任意 CSS 字号。

实际支持为有界子集和忠实源偏移。简单水平表格及有限 presentation MathML 已有显式对象，准入、源码回退和剩余页空间逐行排版见 [EPUB 排版](epub-typesetting.zh-CN.md)。完整 CSS cascade、float、多栏、图片尺寸、通用表格、SVG、完整 MathML 仍超出范围。纯文本回退不能宣传为保留分数、表格或 ruby 语义。

### 6.4 语言与页边策略

保留书籍/资源/span 的 BCP-47 标签。英语地区规则不同，只在元数据支持时启用相应有界集合；未知语言不代表可使用英文断词。出版社软连字符是独立的可选断词机制。

块感知分页可保留标题及少量后文，尽量避免单行段落碎片；超大块/窄几何需放松以保证推进，不能空页、循环或丢字。[CSS Fragmentation](https://www.w3.org/TR/css-break-3/)定义 keep/break、widow/orphan，本项目是小屏适配，不完整实现规范。

后续可考虑字体支持的连字、实测 overhang 的光学边缘、语言相关引号间距；每项都需保源回归及缓存身份变化。没有缓存/增量路径时，不应为不可见细节拖长首开。

## 7. 中日文横排

标点压缩和汉字/ASCII 间距默认开启。`pagination.h` 区分禁则行首和悬挂标点；小假名、迭代/长音符与前文保持，不悬挂到边距。严格断行保护匹配的重复破折号/省略号。行尾禁则与可压缩 side bearing 是独立决策。该有界策略改善中日文横排，不完整实现 JLREQ 或 Unicode 换行。

[CLREQ](https://www.w3.org/TR/clreq/)讨论中文标点、间距和排版，不为此硬件规定通用行高。标点位置与地区/字体有关；SC 派生基底不能证明全部日文或繁中文字形正确。语言 profile 应选择明确规则和可用字体，并公开缺字回退。

在合法边界有界回溯，按策略保留成对破折号/省略号及组合/变体序列。混排尊重显式空格和代码/数学屏障；不能在每个非 ASCII 前加空格，也不能把全部汉字判为中文。测试简繁标点、假名、窄宽度、混合拉丁数字，以及测量/绘制两条路径的同页一致。

## 8. 日文竖排的准确范围

竖排是独立模式，不是截图转 90°。当前路径要求 EPUB 显式声明支持的 `vertical-rl`；汉字、日语标签、RTL 页序均不能单独选择它。纯文本不猜竖排。源要求水平时，日文技术书保持水平。

[CSS Writing Modes](https://www.w3.org/TR/css-writing-modes-3/)区分块流、inline 方向、字形朝向、text-combine；[EPUB 3.3](https://www.w3.org/TR/epub-33/)规定出版结构/页序，两者不同。设备显示旋转也独立。

### 数据与算法要求

- `vertical-rl` 列内从上到下、列从右到左；源码顺序/书签独立于物理轴。
- 使用原生竖排 advance/origin 和括号、标点、假名替代字形。[OpenType 注册特性](https://learn.microsoft.com/en-us/typography/opentype/spec/features_uz)定义 `vert`/`vrt2`；子集需保留或烘焙相关替换/度量。
- 用版本化 [Unicode Vertical_Orientation](https://www.unicode.org/reports/tr50/)分类直立/侧向；“ASCII 旋转，其余直立”会漏标点和变换字形。
- 短横向数字串 tate-chu-yoko 是有界原子，长拉丁串也需明确一致策略。
- 保留 ruby 基字/注音关系，不把读音拼入正文；分组、适配、两轴边缘行为参考 [CSS Ruby](https://www.w3.org/TR/css-ruby-1/)。
- 将日文禁则、缩进、标点间距及分页/分列用于竖排度量。[JLREQ](https://www.w3.org/TR/jlreq/)解释需求及可接受策略差异。
- 保持原生清晰度、源锚点和单调推进；竖排 profile 有独立缓存身份/回归语料。

这些是实现拆分，不表示全部规范已实现。当前已有有界 composer、原生 JP/竖排替代、ruby、显式一/两位数字组合，并保留规范锚点；水平日文保持水平。复杂 CSS、ruby、字形覆盖仍受限，当前范围见 [EPUB 排版](epub-typesetting.zh-CN.md)，不能将下面早期顺序当作完成状态。

### 最初实施顺序

1. 在语义元数据保存 writing-mode、语言、ruby，先测序列化，不启用竖排。
2. 以合成日文和锁定开放 JP 字体建主机预览，比较替代字形、小假名、配对符号、拉丁、ruby、两位组合。
3. 增加轴独立 `InlineMeasure`/`BlockMeasure` 和独立竖排 composer，共享源/语义/边界而非水平坐标假设。
4. 烘焙开放字体子集，准入前量化 flash 增长和最大字形。
5. 测设备 draw/index、旋转、精确锚点迁移、页脚排除、页边，再原生分辨率实屏评估。
6. 对显式声明支持的内容启用，其他结构完整可读回退；更广自动默认需真书覆盖和明确策略。

仅前两步是工程原型，不能称生产竖排支持。合成语料和公开截图不需要用户原书。

## 9. 基准与回归计划

使用源哈希固定、生成参数公开的合成夹具。原生/WASM 字节一致性和主机故障注入验证正确性，不能证明实际 SD 吞吐、无线性能或功耗。首屏、规范索引和缓存发布必须分开计时。

USB 导书默认关闭，保留的 MSC 实现须显式私人实验编译才能启用；源码修正不证明 raw SD 可靠性。

### 持续回归矩阵

使用确定性合成 EPUB 或可再分发的公有领域输入。改变归档/文本大小、章节数、压缩比、语言、XML 节点、长词、重复标点、无用大资源，每夹具固定源哈希。

每 profile 测：

1. 无准备/缓存的首次冷开。
2. 同挂载离书再开。
3. 重启/重挂载再开。
4. 文本不变的一次排版变化。
5. 返回此前排版。
6. 正确准备与过期/损坏/超限准备。
7. 缓存写中断和 SD 移除。
8. 深保存锚点，包括重排后页内位置。
9. 首屏/规范完成/延迟发布及各阶段导航。
10. 真实浏览器准备/AP、源发布前取消、仅源成功后的重试。

报告明确样本数的中位/最差观察、源/文本大小、SPI/CPU、固件身份和缓存结果。不能用热运行对冷基线并归因全部差异。字节计数和阶段日志最能解释提速。

正确性门槛包括完整文本、单调 UTF-8 偏移、index/paint 同断点、精确锚点、无源写入、无 NVS 凭据变化、有界内存、分配失败可恢复、长操作后无排队按键。缺少这些约束的性能结果不可接受。

## 10. 已实现顺序与明确延后范围

现已包括测量工作减少、跨排版内容复用、受控存储期源验证 memo、语义缓存、原生/浏览器生产导入器预处理、有界 EPUB 首屏、独立章节提取与部分页索引恢复、延迟发布、认证文本窗口。主机正确性与硬件性能需要分别验证。排版改进共用度量和缓存身份，不另建无缓存渲染器。

完整章节恢复已实现；deflate/XML 中途挂起、流式章节 DOM 分配、减少 4 MiB 预留仍属后续工作。全源哈希和单次文件系统调用仍影响冷开/取消延迟。完整浏览器 CSS、任意下载字体、完整 MathML 超出有界读器。日文、语义对象和 LAN 有各自的有界契约。USB 导书仍默认关闭，显式实验编译不代表硬件可靠性。
