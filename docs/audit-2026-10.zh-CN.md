## 当时的架构决策

- 应用导航与 SD 书目保持单一所有者任务；并行主机工作不代表设备可并发修改。
- SD 发现与 HTTP 准入通过 `document_format` 共用格式/配额，传输与格式解析独立测试。
- Markdown 拆为保留原文的解析、对象分页、数学布局、原生字库和显示适配器，各边界保留原字节偏移；生成显示字节不成为书签。
- 复用既有英文/CJK 断行和 EPUB/TXT 布局 ID。Markdown 独立缓存身份，临时全文原文回退不覆盖有效缓存。
- 预留可复用 128 KiB 数学工作区及八个有界命令槽，准入失败可用完整原文恢复，后续分页/绘制无需公式解析分配。
- 当时 LAN 仍是[设计提案](lan-design.zh-CN.md)。第二传输实现时再抽取上传存储；当时引入泛用服务框架只会增加未测生命周期。

## 当时的验证与边界

原生套件使用 ASan/UBSan、生产模块、可注入存储/无线电故障边界、真实浏览器 JavaScript、固定公开字库和合成文档。C++11 无异常与固定 ESP32 工具链独立于 C++17 主机测试。主机验证逻辑像素，不验证面板残影或实际电池电流。硬件原始记录不放公开仓库。

数学是有界 TeX 子集；不支持的命令、缺字、超大公式保留完整原文。当时表格仅显示原文，无通用字体 shaping、EPUB 插图渲染、USB 存储、文件夹管理或 LAN 接收。中文排版当时是[可选主机原型](epub-typesetting.zh-CN.md)，设备默认未变。这些是历史边界，当前范围见[格式](markdown.zh-CN.md)、[操作](usage.zh-CN.md)和[功耗证据](power.zh-CN.md)。
